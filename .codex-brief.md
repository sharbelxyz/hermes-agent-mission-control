## Fix 1: Floor Queue Truth Mismatch

**File:** `src/app/floor/page.tsx`

**Issue:** UI count badges (queued, running, done, failed tabs) don't match `/api/runs` truth. Tab totals must be computed from the dataset shown, not hardcoded.

**Current code pattern:**
```typescript
// BROKEN: hardcoded counts
<Pill>queued: 5</Pill>  // May be wrong
<Pill>running: 3</Pill> // May be wrong
<Pill>done: 12</Pill>   // May be wrong
```

**Required change:**
- Extract tab count logic into a helper function `computeTabCounts(runs: RunIndex[])`
- Return object: `{ queued: number, running: number, done: number, failed: number }`
- Compute counts from `runs` array:
  - `queued`: status === 'queued'
  - `running`: status === 'running'
  - `done`: status === 'done'
  - `failed`: status === 'failed'
- Pass computed counts to tab rendering
- **Verify:** Tab totals must always sum to `runs.length`

## Fix 2: Running Badge Semantics (traceRunning vs liveController)

**File:** `src/app/floor/page.tsx`

**Issue:** Badge shows "live" when `data.running` is true, but doesn't distinguish between:
- `traceRunning=true, liveController=false` (row is NOT actually running, just tracing)
- `traceRunning=true, liveController=true` (row IS actually running)

**Current code:**
```typescript
<Pill tone={data.running ? "accent" : "neutral"}>
  {data.running ? "live" : "seen"}
</Pill>
```

**Required change:**
- Add logic: A row is "live" (accent badge) **ONLY if `liveController === true`**
- `traceRunning=true` alone does NOT make it "live"
- Update Pill rendering:
  ```typescript
  const isLive = data.liveController === true;
  <Pill tone={isLive ? "accent" : "neutral"}>
    {isLive ? "live" : "seen"}
  </Pill>
  ```
- Update any other badge/status indicators to use same logic

**Verify:** Search for all references to `data.running` in badge/status context; replace with `data.liveController === true` for visual "live" state

## Fix 3: Empty State for Graph

**File:** `src/app/floor/page.tsx`

**Issue:** When a selected run's graph has no substantive nodes/files, the graph canvas appears broken/empty instead of showing a clear empty state message.

**Current code:** Graph renders with no fallback for empty data.

**Required change:**
- After graph data is loaded, check: `graph.nodes.length === 0 || !graph.hasSubstantiveContent`
- If empty, render:
  ```typescript
  <EmptyState
    icon={<Info />}
    title="No graph data"
    message="This run has not yet produced a graph. Check back after the run progresses."
  />
  ```
- Prevent graph canvas from rendering when no nodes exist
- Style empty state to match surrounding panel

**Location:** Find where graph is rendered in the selected-run detail view, add conditional before `<ReactFlow />` component

## Fix 4: Observability Page Resilience

**File:** `src/app/observability/page.tsx` AND `src/app/api/hermes/observability/route.ts`

**Issue:** Page fetch from `/api/hermes/observability` is fragile:
- No explicit error state display
- No stale data fallback
- Blank/zero display on network failure or API instability
- 24h/7d window failures cascade silently

**Current code (route.ts):**
```typescript
const payload = await collectHermesObservability(window);
cache.set(window, { expiresAt: now + CACHE_MS, payload });
return NextResponse.json(payload);
```

**No error handling in fetch or cache fallback.**

**Required changes:**

### 4a. API Route (`src/app/api/hermes/observability/route.ts`)

- Wrap `collectHermesObservability()` in try-catch
- On error:
  - Return stale cached payload if available (even if expired)
  - If no cache, return error response with `{ error: "...", lastGoodSnapshot: {...} }`
- Add timestamp to all cache entries: `{ expiresAt, payload, cachedAt: Date.now() }`
- Return cache timestamp in response headers: `X-Cache-Age: <ms>`

### 4b. Observability Page (`src/app/observability/page.tsx`)

- Update `getJSON()` to return tuple: `[data, error, cachedAt?]`
- Track state:
  ```typescript
  const [data, setData] = useState<HermesObservability | null>(null);
  const [error, setError] = useState<string | null>(null);
  const [dataAge, setDataAge] = useState<number | null>(null);
  const [isStale, setIsStale] = useState(false);
  ```
- On fetch:
  - If error: display warning banner "Data is stale (last updated X min ago)" with retry button
  - If success but old (> 10 min): display info banner "Last updated X min ago"
  - Always show current data even if stale, with visual indicator
- Test both 24h and 7d windows
- Add explicit error state rendering: `{error && <EmptyState icon={<AlertTriangle />} ... />}`

**Verify:**
- Kill API endpoint, refresh page → shows stale data + warning
- API returns error → shows last-good snapshot + error banner
- Data is fresh → no warning, normal display
